# 디자인 자산 아카이브

기존 AI 스튜디오 프로젝트의 기능과 샘플 데이터 9개를 유지하면서 화면 구성을 정리한 버전입니다.

## 실행

Node.js 22.12 이상을 사용하세요.

```sh
npm install
npm run dev
```

터미널에 표시되는 주소에서 열 수 있습니다. 현재 기능에는 API 키가 필요하지 않습니다.

```sh
npx tsc --noEmit
node --import tsx scripts/check-views.tsx
npm run build
npm run preview
```

## 화면 변경

- 첫 화면: 검색창 → 바닥선 위에 고정 배치한 블록 7개 → 추천 검색어 → 큰 타이틀 순서입니다. 블록은 처음 들어올 때 한 번만 내려앉고, 마우스를 올리면 라벨이 보이며, 클릭하면 바로가기로 이동합니다. 첫 화면에서는 상단 헤더를 숨기고 햄버거만 둡니다.
- 자산 검색: 썸네일과 작업명을 중심으로 표시하고, 6종 상세 필터는 필요할 때 펼칩니다. 격자/목록 전환, 정렬, 과정/교수/프로젝트 묶기를 유지했습니다.
- 상세보기: 미리보기, 핵심 정보, 원본 경로 복사가 먼저 보입니다. 파일 정보, 서체 설명, 태그는 접어서 확인합니다. 정보 수정과 관련 작업 검색을 유지했습니다.
- 자산 등록: 파일 선택 → 정보 확인 → 라이선스의 3단계로 나눴습니다. 파일명/경로 분석, 도구/태그 수정, 서체 확인을 유지했습니다.
- 프롬프트: 비율과 레이아웃을 먼저 표시하고 세부 설정을 접었습니다. 줌, 영역 선택, 참조 작업 전환, 문구 편집과 복사를 유지했습니다. 변경한 설정은 즉시 초안에 반영됩니다.
- 라이선스: 상태별 검색과 정렬을 유지하고, 계약 정보는 행을 펼쳐 확인합니다.
- 파일명 규칙: 실시간 예시, 순서 변경, 구분자/버전 설정, 도구/작업 유형 편집을 유지했습니다. 메뉴의 사용자 모드를 관리자로 바꾸면 접근할 수 있습니다. 저장한 규칙은 이 브라우저의 규칙 편집 화면에 유지됩니다.

## 디자인

- Pretendard 400/600/700/800을 프로젝트에 포함해 외부 폰트 CDN 없이 불러옵니다.
- 아이보리 `#F7F3EF`, 블랙 `#191919`, 코발트 블루 `#246BFD`, 테두리 `#E3E0DC`를 사용합니다.
- 첫 화면은 데스크톱·모바일 모두 화면 높이에 맞춰 검색창, 도형, 타이틀을 한 화면에 배치합니다. 짧은 화면에서는 보조 문구와 푸터를 줄입니다. 검색 결과 등 내부 화면은 자연스럽게 스크롤되며, 모바일 작업 목록은 2열로 표시합니다.
- 일본어 문구, 참고 자료의 브랜드/로고는 화면에서 사용하지 않습니다.

## 샘플 동작 범위

이 프로젝트는 원본과 동일하게 프런트엔드 샘플입니다. 실제 디자인 파일, NAS, 사내 라이선스 DB, 이미지 생성 API는 연결되어 있지 않습니다.

- 원본에 실제 작업 이미지가 없어 기존 메타데이터를 바탕으로 그래픽 미리보기를 표시합니다. 실제 디자인 원본과 다릅니다.
- 원본 경로 복사는 등록된 경로 문자열을 복사합니다. 샘플 다운로드 버튼은 실제 파일이 연결되지 않았음을 안내합니다.
- 작업 등록/수정은 실행 중인 화면의 메모리에 반영됩니다. 새로고침하면 기본 샘플로 돌아갑니다.
- 라이선스 갱신은 신청 문구 복사까지 지원합니다. 외부로 전송하지 않습니다.
- 사용자 모드는 샘플 권한 확인용이며 실제 인증을 대신하지 않습니다.
- 프롬프트는 현재 선택값을 조합한 편집 가능한 문구입니다. 이미지 생성 API를 호출하지 않습니다.

## 확인

7개 화면의 서버 렌더링, 다중 검색어/특수문자 검색, 9개 자산의 상세 정보 표시, TypeScript 검사와 프로덕션 빌드를 통과했고 샘플 데이터 파일이 원본과 동일함을 확인했습니다. 제공된 환경에서 미리보기 데몬을 사용할 수 없어 실제 브라우저에서의 클릭 및 모바일 시각 검수는 수행하지 못했습니다.

## 수정과 테스트

GitHub에 업로드하면 push와 PR마다 `.github/workflows/check.yml`의 타입 검사, 검색/서버 렌더링 테스트, 빌드가 실행됩니다. 브라우저 클릭 테스트와 배포는 이 워크플로에 포함되지 않습니다.

로컬에서는 `npm run check`로 같은 검사를 실행합니다.

작은 단위로 수정 → 검사 통과 → 배포 → 실제 화면 확인 순서로 진행하세요. 화면/기능 문제가 있으면 GitHub의 “화면 · 기능 수정” 이슈 양식에 재현 방법과 원하는 결과를 남길 수 있습니다.

실제 화면에서는 검색어 입력, 필터 초기화, 자산 상세보기와 수정, 3단계 등록, 프롬프트 설정/복사, 모바일 줄바꿈을 우선 확인합니다.


### 인터랙션 구현

Matter.js로 7개 블록의 중력·충돌·드래그를 계산하고, 화면은 접근 가능한 HTML 버튼으로 표시합니다. 멈춘 블록은 계산을 쉬고, 탭이 가려지면 애니메이션 루프를 중지합니다. 화면 크기가 바뀌면 블록 크기와 경계를 다시 맞춥니다. 첫 화면의 화면 높이 고정과 한국어/Pretendard/아이보리·블루 기준은 유지합니다.
